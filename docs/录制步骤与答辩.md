## 必须理解的原理与答辩问题

| 问题 | 解释要点 |
| --- | --- |
| Npcap 在哪里采集数据？ | 普通网卡在链路层附近提供帧，loopback 提供特定链路头；应用通过 pcap_datalink 判定格式。混杂模式无法突破交换网络和加密协议的可见范围。 |
| 为什么保存两种长度？ | wirelen 是线上报文长度，caplen 是当前保存字节数；snaplen、捕获截断会使二者不同。 |
| 没有流量时如何停止？ | Npcap 非阻塞读取，等待周期 5 ms；停止事件由采集线程观察，该线程释放句柄，后续线程完成队列数据。 |
| 两类过滤在哪里执行？ | BPF 在捕获路径减少交给程序的数据；显示过滤在解析字段上执行，文件导出保存完整会话。 |
| 为什么 80 端口无法证明 HTTP？ | 端口仅是端点属性；HTTP 需要合法起始行、头部和 TCP 连续数据。TLS 应用数据默认不可解密。 |
| TCP 双向数据如何识别？ | IP 版本和规范化双向端点组成连接键，首次观察方向定义 A/B，SYN、ISN、关闭状态和空闲时间区分代次。 |
| 重传与重叠如何处理？ | 以序号计算区间，已观察字节优先，只补充未观察区间，重复和冲突分别计数；缺口保持为空。 |
| Content-Length 和 chunked 如何定界？ | 前者按字节计数，后者解析长度行、块终止符与尾部；冲突长度、未支持编码和不完整数据保留状态。 |
| 普通 PCAP 能否恢复 PID？ | PCAP 网络数据没有本机 PID。PID 来自同期 GetExtendedTcpTable 和进程创建时间观察，配套 JSON 才保留关联证据。 |
| 为什么 PID 需要创建时间？ | 操作系统可能复用 PID；创建时间与端点、采样时间共同约束身份，仍无法完全观察采样间隔内的极短复用。 |
| 为什么 Lua 校验完整文件？ | 单个包或相同五元组无法保证来自同一捕获；文件摘要、包数、逐包摘要和纳秒时间共同防止误配。 |
| 插件分别增加什么？ | Dissector 新增 LABDEMO 协议树；Postdissector 加入外部进程证据；Listener 读取已解析字段统计请求响应。 |
| 如何证明自研解析正确？ | 基于明确期望的离线边界样本、真实本机流量，以及同一 PCAP 的 TShark 字段交叉验证。测试通过不代表所有网络环境和畸形输入穷尽。 |
| 什么是本项目原创部分？ | Npcap ctypes 封装、协议字段分析、队列与 GUI、显示过滤语义、TCP 重组和进程关联、配对格式与 Lua 逻辑。Qt、Scapy PCAP 读写、Lark、psutil、dkjson、sha2 属于复用依赖。代码由 AI 辅助实现，应如实说明个人审阅与理解。 |
