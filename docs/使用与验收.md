# 实验 1A 使用与验收

平台为 Windows 11 x64。实测环境使用 Python 3.12.14、PySide6/Qt 6.12.0、Npcap 1.90、TShark 4.6.9。基础抓包、协议分析、TCP 重组和进程观察均由 Python 程序执行。未安装 Wireshark 时可运行 GUI 和离线 PCAP 分析；Lua 扩展验收需要 Wireshark/TShark。

## 安装与启动

安装 Python 3.12 x64 和 Npcap x64，保留 Npcap loopback 支持。本机 Npcap 开启管理员访问限制，因此实时抓包和完整测试需要从管理员 PowerShell 启动。保持已有安全策略；权限不足时程序报告失败，离线分析仍可使用。

在源码目录执行：

```powershell
.\setup.ps1 -PythonExe 'C:\实际安装位置\python.exe' -Development
.\start.ps1
```

setup.ps1 创建 .venv312 并安装固定版本依赖。Python 3.13 x64 也允许安装，但本项目没有对其执行完整验收。系统或 Python 环境中的 Microsoft Visual C++ x64 运行库必须满足 Qt 要求；本机原有 Anaconda Python 3.11.4 携带的旧运行库无法加载所选 Qt，本次使用独立 Python 3.12.14 验证环境，未修改全局 Python。

浅色界面分为“数据包”和“TCP 流”两个页面。选择网卡，展开“过滤与捕获参数”设置 BPF、捕获长度、驱动缓冲和超时，再点击“开始新会话”。“停止”结束采集并完成已接受数据的解析和写入。“清空显示”清除界面窗口；完整文件保留。“开始新会话”创建独立会话。每次会话位于 output/sessions/UUID/，包含 capture.pcap 和 metadata.sqlite。完整会话达到 256 MiB 时停止并提示，之前的文件保留。

“数据包”页面使用协议配色、独立列宽和可拖动分隔条；详情树可以展开嵌套字段，右侧显示原始字节。“TCP 流”页面按 PID/完整进程名筛选，双击一条流打开双向内容、连接时间线、HTTP 消息和本机进程观察。内容格式下拉框切换文本/十六进制。“查看关联数据包”返回包列表并应用流编号过滤。无效显示过滤在输入框下方提示，当前有效结果保留。

快捷键：F5 开始新会话，Shift+F5 停止，Ctrl+O 打开 PCAP，Ctrl+S 导出，Ctrl+L 定位显示过滤。底部五项指标分别显示捕获数、显示数、保存数、捕获数据量和平均包速率，丢包/队列丢弃单独显示。1024×720、1280×800、1440×900 窗口尺寸通过 Qt 实际控件边界和导航检查；没有使用截图进行视觉检查。

停止后使用“导出 PCAP + PID”，选择尚不存在的文件名。导出在后台执行，产生 capture.pcap 与 capture.pcap.labproc.json。重新打开带配套 JSON 的 PCAP 会校验摘要，保留原始会话 UUID、包号和进程观察。只打开普通 PCAP 时进程状态为未知。程序不支持直接读取 PCAPNG，可使用 Wireshark 的 editcap -F pcap 转换；转换会使既有进程配对失效。

## 显示过滤语法

抓包过滤由 pcap_compile/pcap_setfilter 执行，例如 `tcp or udp port 53`。它决定进入程序的包。显示过滤使用 Lark 解析自定义语法，筛选当前内存窗口，导出的完整原始会话保持原状。

支持 `and`、`or`、`not`、括号、`== != > >= < <=`、非负整数和双引号字符串。优先级为比较/存在性、not、and、or。字符串比较区分大小写。空表达式显示全部。最大长度 1024 字符、嵌套 32 层。程序不执行 eval，也不提供 Wireshark 全部语法、CIDR、正则表达式或 contains。

协议存在性：ethernet、vlan、loopback、arp、ip、ipv4、ipv6、tcp、udp、icmp、icmpv6、dns、http、tls、labdemo。布尔状态使用 `frame.truncated`、`ip.fragmented` 或前置 not。

数值字段：port、pid、tcp.srcport、tcp.dstport、udp.srcport、udp.dstport、tcp.stream、frame.number、frame.original_number、frame.len、frame.caplen、dns.id、dns.rcode、http.status、labdemo.type、labdemo.request_id、tcp.flags、tcp.seq、tcp.ack、vlan.id。

字符串字段：addr、src、dst、ipv4.src、ipv4.dst、ipv6.src、ipv6.dst、process.name、process.status、http.method、http.path、http.host、http.version。addr/port/PID 等多值字段中，等值比较任一元素匹配即可；不等比较要求存在元素且全部不等。缺失字段的比较结果为假。

```text
tcp and (port == 80 or port == 18080)
addr == "127.0.0.1" and not udp
http and http.method == "GET"
tcp.stream == 0
pid == 12345
process.name == "python.exe"
frame.truncated or ip.fragmented
```

PID 请替换为实际值。HTTP 字段出现在完成结构识别的包及相关后续数据包上；较早的分段包仍显示 TCP。完整 HTTP 头部和双向内容在“追踪 TCP 流”中查看。

## 可复现流量与验收

```powershell
.\.venv312\Scripts\python.exe -m labsniffer.traffic --port 18080 --flows 3
.\.venv312\Scripts\python.exe -m labsniffer.traffic --host ::1 --port 18081 --flows 3
.\.venv312\Scripts\python.exe -m labsniffer.demo exercise
.\run_tests.ps1
```

完整验收使用本机端口 53、80、18080、18081、18082、45990 和动态端口。端口冲突会明确失败，需要先释放对应测试端口。所有客户端和服务器只使用 127.0.0.1 或 ::1。持续抓包测试会打开真实 Qt 窗口，并测量事件处理间隔，不采集截图。

run_tests.ps1 在 output/acceptance/运行编号/ 保存 pytest.log、junit.xml、results.json、environment.json、验收记录.md、TShark 调用日志和 PCAP 证据；latest.json 指向最新运行。测试顺序保证 TCP/PID 前置证据在 Lua 校验之前产生。本机无 TShark 时插件测试显示 SKIP；缺少 Npcap 或权限时完整验收应先补足环境。`run_tests.ps1 -Offline` 只执行离线检查，未运行项目明确列为未验证。

输出的 offline_labdemo.pcap 和 offline_tcp_gap_retransmission.pcap 是人工构造的离线边界样本；real_http、child、gui_export 及会话 capture.pcap 来自本机真实网络。详细来源见 evidence 内对应 JSON，不能把离线样本称为真实抓包。

## 有界保留与状态解释

三个队列默认各 2048 条；GUI 每 100 ms 最多处理 300 包或 25 ms，保留 5000 包/32 MiB 原始字节。采集队列满时增加采集丢弃计数；GUI 队列满时只丢弃该界面的更新，磁盘仍保存解析后的包。磁盘队列使用反压。TCP 最多保留 512 流，总有效载荷 32 MiB，每方向 256 KiB/4096 区间，事件时间线每流 256 条。超过限制后明确标为不完整。流内存窗口淘汰后可从完整 PCAP 重新分析。

线上长度与捕获长度分别保存。状态栏中的速率是本次会话平均值。Npcap 驱动丢包和程序队列丢弃分别报告；接口丢包无法证明可用时显示未知。测试环境的数据只代表该次本机负载，不代表最大吞吐率。

进程状态 observed 表示时间邻近的 Windows 连接表观察，包含进程创建时间与采样时刻；它仍具有周期采样的不确定性。unknown、sampling_error、process_exited、permission_denied、uncertain_reuse、uncertain_stale、uncertain_scope 均不输出猜测 PID。仅 TCP 本机端点参与进程关联；UDP 和远端进程不推断 PID。
